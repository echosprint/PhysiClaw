description: 每个 App 一个 YAML 文件，确定性地走完一项任务。你声明每一步，指挥器只执行你声明的内容，模型只在你划定的范围内做决定。
---

剧本把一项 App 任务写成一条路线：走位必须停留的页面，与它做出的动作交替出现。大多数动作是录制好的宏，不花 token。必须做判断的地方，用 `agent` 步骤把你的提示词和少数几个工具交给模型。必须由人批准的地方，用 `ask` 给用户发消息并等待。剧本声明什么就运行什么。后台不会自行恢复、重试或解锁。

## 创建剧本包

先脚手架，再编辑文件：

```bash
physiclaw playbooks init taobao
```

<FileTree>
- ~/.physiclaw/playbooks/
  - README.md
  - taobao/
    - PLAYBOOK.yml
    - example.yml
    - macros/
      - example-move/
        - MACRO.yml
</FileTree>

一个包就是一个文件夹。`PLAYBOOK.yml` 是清单：这个 App 是什么、它的剧本共用什么，即占位符、地标和多条路线都会落到的页面。它从不包含路线，每个段落都可选，空文件也是合法的包。每个剧本各自一个文件放在旁边，像 skill 一样以 `name` 和 `description` 开头；名字必须与文件名一致，所以 `buy.yml` 就是 `taobao/buy`。路线共用的手法放在 `macros/` 下作为包宏。脚手架生成的示例剧本就是格式参考，每种条目都带注释说明用途和要求。

## 路线

剧本的路线由六种条目组成：

- `page` 是走位必须到达的页面，每次都检查。锚点只声明一次，写在路点旁或 `pages:` 里，其他地方只写名字。
- `start` 是冷启动，至多一个，紧挨第一个页面之前。
- `do` 运行一个录制好的宏。它后面的页面就是落地检查。
- `agent` 把这一步交给模型。你的 `prompt:` 就是全部指令。没有 `tools:` 时是纯文本调用，填写 `returns:`。有工具时它在屏幕上行动，用行文本、授予的地标或授予的宏作答，直到它后面的页面出现。
- `ask` 给用户发消息并等待。回复按你声明的 `yes:` 和 `no:` 词读取。其他回复交给模型处理。
- `tell` 给用户发消息，然后暂停到下次唤醒。

一条最小路线：

```yaml
route:
  - start: app
    macro: {steps: [{name: open, tool: tap, with: {label: "the app icon", bbox: [0.72, 0.42, 0.91, 0.55]}}]}
  - page: home
    anchors: {or: ["推荐", "关注"], region: top}
    recover: {tool: force_quit}
  - do: search
    with: {keyword: "{inputs.keyword}"}
  - page: results
    anchors: {and: ["综合", "销量"]}
    recover:
      occluded: {tool: tap, with: landmarks.dismiss}
      elsewhere: {tool: go_back}
      limit: 2
```

## 恢复

页面的 `recover:` 是唯一的恢复手段。在清单里声明的页面带着每条路线都继承的手法，路线也可以声明自己的手法来覆盖。一只手覆盖任何偏离。按读法分开的手对应匹配器的几种读法：`occluded` 是页面本身被弹层或弹窗盖住，`locked` 是手机显示锁屏，`elsewhere` 是任何其他屏幕。`limit:` 限制该页面每次走位的尝试次数。手运行后，走位重新检查页面，仍不对就从路线顶部重来。没有 `recover:` 的页面当场交接。

## 开场

每次唤醒都先走通道包自己的剧本 `channel/boot.yml`，走法和其他剧本一样。它的路线是会话页面和到达它的手法，然后是 `activate`，只有这个文件能带的一步：对照已启用的剧本读取会话，把匹配的剧本交给走位。手法和限制像任何路线一样改，用 `physiclaw playbooks step channel/boot --reply "帮我买五常大米"` 单步调试。

```yaml
route:
  - page: thread
    recover:
      locked: {tool: unlock_phone}
      occluded: {macro: open}
      elsewhere: {macro: open}
      limit: 4
  - activate: parse
    limit: {scrolls: 2}
```

## 金额

支付类 `ask` 用 `total:` 声明总额旁边的标签。该行上的金额填入 `{ask.total}`，消息必须引用它。`yes:` 回复把同意绑定到这个数字。支付动作必须紧跟在 `ask` 之后，`ask` 必须声明 `resume:` 回到 App，且只在屏幕仍显示已同意的金额、且询问之后没有出现更高金额时才会执行。

```yaml
  - ask: confirm-pay
    approve: payment
    total: "合计"
    message: "实付 ¥{ask.total}，回复 好的 支付，或 不用 取消。"
    yes: ["好的"]
    no: ["不用"]
    wait: {seconds: 45, rounds: 3}
    resume: {steps: [{name: reopen, tool: tap, with: {label: "the app icon", bbox: [0.72, 0.42, 0.91, 0.55]}}]}
  - do: pay
    irreversible: payment
    macro:
      steps:
        - {name: pay-button, tool: tap, with: {label: ["免密支付", "立即支付", "提交订单"], bbox: [0.37, 0.92, 0.63, 0.95]}}
        - {name: settle, tool: wait, with: {seconds: 4}}
  - page: paid
    anchors: {or: ["支付成功", "付款成功"]}
```

## 启用前先测试

按从便宜到真实的阶梯来。先校验，再把录制的屏幕送入真实路线离线回放，然后在手机上逐节点单步，再端到端排练，最后校准页面并设置 `enabled: true`。所有排练命令都需要 `physiclaw mcp` 已在运行，且不会自行启动它。

```bash
physiclaw playbooks check
physiclaw playbooks replay taobao/buy --session <id> -i user_said="帮我买五常大米" -o parse.keyword=五常大米
physiclaw playbooks step taobao/buy -i user_said="帮我买五常大米"
physiclaw playbooks run taobao/buy -i user_said="帮我买五常大米"
physiclaw playbooks pages calibrate taobao
```

单步就是调试器。每次调用都重新读取包文件，在存储的游标处运行该节点，游标一动就暂停，并打印每个判定、模型回答和宏步骤。`--at` 重跑刚改过的节点，`--start-at`/`--stop-after` 把它的宏收窄到一个手势，`--output` 预置纯文本 agent 的答案，`--reply` 预置 ask 读取的回复，`--raw` 原样打印 agent 节点每次模型往返的发送内容和返回内容，`--json` 输出结果和位置供 agent 循环读取。单步时用户通道是虚拟的，ask 读取预置的回复；`run` 则等待真实联系人回复。两者都驱动真实手机，单步走到支付节点就会真的付款。

```bash
physiclaw playbooks step taobao/buy                              # 下一个节点
physiclaw playbooks step taobao/buy --at search --stop-after paste
physiclaw playbooks step taobao/buy --reply 好的 --to end
physiclaw playbooks step taobao/buy --status --json
```

`physiclaw studio` 把同一套单步放进浏览器面板，与相机和虚拟屏并排，共用同一个位置文件，所以桌前的人和终端里的 agent 可以轮流推进同一次走位。

## 最佳实践

- 能录制的动作都录制。`agent` 步骤是例外，由前后页面、`limit:` 和你授予的工具围住。
- 授予地标和宏，而不是描述它们。`give: [landmarks.cart, macros.add-to-cart]` 把五次自由点击变成一次作答。
- 每个页面声明四个以上锚点。只有三个时，一次 OCR 漏读就会让页面低于阈值而读成未知。`playbooks check` 会提示。
- 用 `page:` 把地标限定在它所在的页面，模型就不会被授予屏幕上不存在的位置。
- 关注 `physiclaw playbooks stats`。反复交接的节点就是要修的地方，`propose` 会打印对应命令。
